# 平板 / 折叠屏适配可行性分析

> 文档目的：评估 ComposeYdWeather 当前能否在平板、折叠屏（展开态）等大屏设备上获得良好体验，指出现状问题，并给出分阶段的改造方案。
>
> 参考截图见 [`docs/screenshots/`](./screenshots/)（手机端现有 UI：天气主页、15日预报曲线/列表、观测数据面板、生活指数弹窗、城市管理及其多选/滑动删除、城市选择、城市搜索）。

---

## 一、结论速览

**当前可以运行，但没有做大屏适配，大屏体验较差。**

- ✅ 技术上能跑：应用基于 Jetpack Compose，所有界面用 `fillMaxSize` / `fillMaxWidth` 自适应填充，放到平板/折叠屏上**不会崩溃、不会裁切**，能正常显示。
- ⚠️ 体验不佳：所有页面都是**为竖屏手机单列设计**的。在平板横屏或折叠屏展开后，会出现：
  - 内容被拉伸成一条**超宽单列**，左右大量留白，天气卡片横向拉得很长；
  - 顶部温度（92sp 等）、卡片间距等按手机比例设计，大屏上显得空旷；
  - 城市选择的「热门城市」固定 4 列、城市管理单列列表，在宽屏上无法利用横向空间；
  - 没有 list-detail（左列表 + 右详情）这类大屏典型布局。
- ❌ 完全没有引入任何大屏自适应能力（见下文「现状盘点」）。

**一句话**：能用，但要做到"适配良好"需要一轮针对性改造，工作量中等。

---

## 二、现状盘点（代码层面）

### 1. 没有引入任何窗口尺寸感知 API

全项目检索 `WindowSizeClass` / `currentWindowAdaptiveInfo` / `calculateWindowSizeClass`：

- **0 处使用**。即应用无法区分"手机/平板/折叠屏展开"，所有设备走同一套布局。
- 仅 `WeatherBgEditScreen.kt` 用到 `BoxWithConstraints`，且只用于背景编辑的尺寸计算，与响应式无关。
- 依赖里也**没有** `androidx.compose.material3.adaptive` / `material3-window-size-class` / `androidx.window` 等大屏相关库。

### 2. AndroidManifest 未声明大屏 / 折叠相关属性

[`app/src/main/AndroidManifest.xml`](../app/src/main/AndroidManifest.xml)：

- 未锁定方向（没有 `android:screenOrientation`）——**好事**，意味着可旋转、可在折叠屏自由窗口运行。
- 未声明 `android:resizableActivity`（targetSdk 36 默认 `true`，所以可进多窗口/分屏）。
- 未处理 `android:configChanges`，旋转/折叠会重建 Activity（Compose 状态靠 `rememberSaveable`/ViewModel 保留，需逐页确认）。

### 3. 布局全部是"竖屏单列"假设

| 页面 | 当前实现 | 大屏问题 |
|------|----------|----------|
| 天气主页 [`WeatherContentList.kt`](../app/src/main/java/com/yd/weather/widget/WeatherContentList.kt) | 单个 `LazyColumn`，卡片 `fillMaxWidth` + 固定 `ITEM_PANEL_MARGIN=16dp` 边距 | 宽屏下卡片被拉成超宽长条，单列浪费横向空间 |
| 头部 [`WeatherHeaderWidget.kt`](../app/src/main/java/com/yd/weather/widget/WeatherHeaderWidget.kt) | 温度字号写死（92sp/86sp 等），`fillMaxWidth` | 大屏比例失衡，居中后两侧空旷 |
| 城市管理 [`CityManagerPage.kt`](../app/src/main/java/com/yd/weather/main/CityManagerPage.kt) | 单列 `LazyColumn`，卡片满宽 | 宽屏下每张卡片过长，应改多列网格 |
| 城市选择 [`SelectCityScreen.kt`](../app/src/main/java/com/yd/weather/selectcity/SelectCityScreen.kt) | 热门城市 `GridCells.Fixed(4)` 写死 4 列，`padding(horizontal=20dp)` | 宽屏下每格过宽，应随宽度增加列数 |
| 弹窗（空气质量/生活指数等）[`dialog/`](../app/src/main/java/com/yd/weather/dialog/) | 贴底/全宽弹出 | 大屏应改为居中限宽对话框 |
| 多城市横滑 | `HorizontalPager` 满屏一页一城市 | 大屏可考虑一屏多列或 list-detail |

### 4. 间距/字号是常量

[`config/Constants.kt`](../app/src/main/java/com/yd/weather/config/Constants.kt) 里 `ITEM_PANEL_MARGIN`、头部高度 `WEATHER_HEADER_MAX/MIN_HEIGHT` 等都是固定值，没有按屏幕宽度档位区分。

## 三、目标体验（大屏应该长什么样）

参考 iOS 天气 / 系统天气在 iPad 上的做法，建议：

1. **天气主页（展开态 / 平板横屏）**
   - 方案 A（推荐，改动小）：**限制内容最大宽度**（如 `widthIn(max = 600dp)` 居中），超出部分留白。立刻消除"超宽长条"，体验马上可接受。
   - 方案 B（更佳，改动大）：**双栏瀑布**——把天气卡片分成两列（如逐小时/多日/空气质量分列），用 `LazyVerticalStaggeredGrid` 或两个 `LazyColumn`。
   - 方案 C（最佳）：**List-Detail**——左侧城市列表常驻，右侧当前城市天气详情，类似 iPad 天气。利用 `material3-adaptive` 的 `ListDetailPaneScaffold`。

2. **城市管理 / 城市选择**：随宽度自动增加列数（`GridCells.Adaptive(minSize = …)` 取代 `Fixed(4)`）。

3. **弹窗**：大屏改为居中、限宽（如 `max 480dp`）的对话框，而非贴底全宽。

4. **折叠态切换**：折叠/展开、旋转时状态不丢失（ViewModel + `rememberSaveable` 已具备基础，需逐页验证）。

## 四、分阶段改造方案

### 阶段 0：基础设施（必做，约 0.5 天）

1. 引入依赖（`gradle/libs.versions.toml` + `app/build.gradle.kts`）：
   ```kotlin
   implementation("androidx.compose.material3.adaptive:adaptive:<version>")
   implementation("androidx.compose.material3.adaptive:adaptive-layout:<version>")
   implementation("androidx.compose.material3:material3-window-size-class:<version>")
   ```
2. 在 `MainActivity` / 顶层用 `currentWindowAdaptiveInfo()` 拿到 `WindowSizeClass`，通过 `CompositionLocal` 下发给各页面，让 UI 能按 `Compact / Medium / Expanded` 分档。

### 阶段 1：低成本快赢（建议优先，约 1 天）

> 只改"宽度"，不改信息架构，收益/成本比最高。

1. **天气主页内容限宽居中**：给 `WeatherContentList` 的 `LazyColumn` item 包一层 `widthIn(max = 600dp)` 并水平居中（Expanded 档生效，Compact 档保持满宽）。
2. **网格列数自适应**：
   - `SelectCityScreen` 的 `GridCells.Fixed(4)` → `GridCells.Adaptive(minSize = 96.dp)`（或按 WindowSizeClass 给 4/6/8 列）。
   - 搜索结果列表同理限宽居中。
3. **城市管理列表**：Expanded 档用 `LazyVerticalGrid`（2~3 列），Compact 档保持单列。
4. **弹窗限宽居中**：`dialog/` 下各弹窗在大屏改为居中 + `widthIn(max = 480.dp)`。

完成阶段 1 后，平板/折叠屏体验即可从"勉强能用"提升到"协调可用"。

### 阶段 2：List-Detail 大屏布局（可选，约 2~3 天）

1. 用 `ListDetailPaneScaffold`：左 = 城市管理列表，右 = 选中城市天气详情。
2. Compact 档自动退化为单页导航（与现状一致），Expanded 档双栏并存。
3. 需要调整导航：城市列表点选后更新右侧 detail，而非整页跳转。

### 阶段 3：折叠屏铰链 / 姿态（可选，锦上添花）

1. 引入 `androidx.window` 监听 `FoldingFeature`，在半折叠（TableTop）姿态下做特殊布局（如上半屏信息、下半屏列表）。
2. 处理铰链遮挡区域（HingePadding）。

## 五、风险与注意点

- **状态保留**：旋转/折叠会重建 Activity。需逐页确认滚动位置、弹窗开关、城市选中等用 `rememberSaveable` 或 ViewModel 持有，否则会"跳回顶部/弹窗消失"。
- **共享元素转场**：项目用了 `SharedTransitionLayout`，改 List-Detail 时要重新设计转场，避免大屏下动画错位。
- **背景渐变 / 模糊**：`AppState` 的背景色按整屏生成；若改双栏，需确认 backdrop 模糊区域与新布局对齐。
- **预览（Preview）**：建议给关键页面补 `@Preview` 的平板尺寸（如 `widthDp=840, heightDp=1280`）便于调试。
- **测试设备**：用 Android Studio 的 Resizable Emulator（支持手机/折叠/平板一键切换）验证。
